Subsystem architecture · the scoreboard

Outcomes become scores.

One subsystem owns all the numbers. It consumes reward.signal events and maintains two ledgers: the faculty grade that drives the reinforcement loop, and the student rank & XP that drives motivation. The asymmetry is the whole design — penalties only ever touch faculty.

ledger 1=faculty grade ledger 2=student rank / XP rule=student reward ≥ 0 output=grades · ranks · boards

Faculty grade

From a stream of rewards to a letter.

Computation

The grade is an exponential moving average of reward, normalized to a 0–100 score and mapped to a letter. Recent outcomes weigh more, so a teacher can recover after a Provost update.

The asymmetry

Why it's built this way.

All penalties flow to faculty

The student ledger is monotonic — it only rises. Every negative reward lands on a teaching agent. This is the single rule that keeps the learner engaged while making the faculty relentlessly accountable. The reinforcement loop in the Faculty Agent spec is this rule, applied.

student: reward ≥ 0 always · faculty: the full gradient
